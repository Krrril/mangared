### Инцидент (кратко)
- Симптом: сайт открывался и через 2–4 сек весь контент пропадал (чёрный экран).
- Причина: в `ImageWithRetry.tsx` (коммит `b28a5d4`) был inline ref-колбэк (`ref={(el) => {...}}`), вызывавший `setState` напрямую. React пересоздаёт такой колбэк на каждом рендере → detach/attach → setState на каждый рендер → бесконечный цикл → `Maximum update depth exceeded` (React error #185) → необработанное исключение → React размонтирует всё дерево → чёрный экран.
- Исправление (ветка `fix/black-screen`, коммит `790fe5c`): стабильный `useRef` + `useEffect([attemptKey])` вместо inline-колбэка. Плюс добавлен `ErrorBoundary.tsx`: корневой (вокруг всего `App.tsx`, с экраном "Что-то пошло не так" / кнопкой "Обновить страницу") и точечный (вокруг `ImageWithRetry` в `CoverPlaceholder.tsx`) — чтобы падение одной обложки не роняло весь сайт.
- Как проверено: preview-деплой Vercel для ветки был закрыт SSO-логином (недоступен без учётки) — **это НЕ было проверено на preview**. Вместо этого: (1) локально, на чистом перезапущенном dev-сервере и в заведомо новой вкладке (чтобы исключить устаревший буфер консоли) — ошибка не воспроизвелась; (2) после мерджа в `main` и реального деплоя — вживую открыты оба прод-домена, desktop и мобильная эмуляция, 4 страницы, без ошибок и без исчезновения контента.
- Безобидные 404 в консоли читалки — это штатные попытки `ImageWithRetry` обратиться к запасным адресам страницы (retry-логика), не крах.

```bash
git log --oneline -5          # найти последний хороший коммит
git revert <плохой-коммит>    # НЕ reset --hard, НЕ force-push
git push origin main
```
Подождать деплой на Vercel (обычно ~1 минута, проверять через `GET https://api.github.com/repos/Krrril/mangared/commits/<sha>/status`, context `Vercel`, ждать `state: success`), открыть прод, проверить.
