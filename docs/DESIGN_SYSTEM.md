# DESIGN_SYSTEM.md — MangaGreen

Разбор снят вручную со скриншотов (веб-версия "главная с сайдбаром" и
мобильный набор экранов), которые приложил пользователь. Скриншоты — не
файлы на диске, а картинки в чате, поэтому точные hex-коды ниже — это
**приближение на глаз**, а не пипетка по пикселю. Как только появятся
исходники в Figma/PNG — стоит сверить и подправить значения здесь же.

Бренд на референсах подписан "MangaVerse" — в реальном проекте везде
заменяем на **MangaGreen** (логотип, тексты, промо-карточки).

экономно: primary-кнопки, активный пункт навигации, бейджи
("Популярное", "NEW"), ссылки "Все →". Специально не самый яркий/неоновый
оттенок зелёного ("нежно-зелёный") — чтобы не резал глаз на тёмном фоне и
не спорил с `--success` (см. ниже).

## 2. Типографика

Шрифт на скриншотах — геометричный гротеск с высокой строчной высотой,
визуально ближе всего к **Inter** (он бесплатный, отлично работает в
браузере и это стандарт де-факто для такого рода интерфейсов). Берём его
как рабочий шрифт, пока нет уточнения от дизайнера.

```css
font-family: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
```

| Стиль | Размер / вес | Где |
|---|---|---|
| `display` | 32px / 700 | Заголовок hero-баннера ("Solo Leveling") |
| `h1` | 24px / 700 | Заголовок страницы тайтла |
| `h2` | 18–20px / 700 | Заголовки секций ("Популярное сегодня") |
| `body` | 14px / 500–600 | Название карточки, пункты меню |
| `body-sm` | 13px / 400 | Описания, вторичный текст |
| `caption` | 12px / 400–500 | "Глава NNN", таймстемпы, подписи под иконками (мобильный tab bar) |

Логотип "MangaVerse" → "MangaGreen": bold, ~18px, рядом — квадратная иконка
с градиентом (книга/страница), скруглённый квадрат ~8px радиус.

## 3. Отступы и сетка

Похоже на шкалу с шагом 4px:

`4 · 8 · 12 · 16 · 20 · 24 · 32 · 48px`

- Паддинг карточек: 12–16px
- Промежуток между карточками в сетке/карусели: 16–20px
- Паддинг сайдбара: 20–24px по горизонтали
- Паддинг секций контента: 24–32px

Веб-раскладка: три колонки — сайдбар (фикс. ширина, ~220–240px) / основной
контент (гибкая, скроллится) / правая панель (фикс. ширина, ~280–320px,
"Продолжить чтение", "Последние обновления"). На узких экранах правая
панель и затем сайдбар должны схлопываться — на скриншоте это не показано,
это стандартное поведение, которое проектируем сами.

## 4. Радиусы скругления

| Токен | Значение | Где |
|---|---|---|
| `--radius-sm` | 6–8px | Бейджи рейтинга, мелкие теги |
| `--radius-md` | 12px | Карточки тайтлов, инпуты |
| `--radius-lg` | 16–20px | Hero-баннер, промо-карточки, обложка на странице тайтла |
| `--radius-full` | 9999px (pill) | Primary-кнопки ("Читать", "Оформить Premium"), чипы категорий, поле поиска, сегментированные переключатели |

## 5. Компоненты

### Кнопки

- **Primary** — заливка `--accent` (или градиент), белый текст, форма pill
  (`radius-full`), паддинг ~12px×24px, bold. Пример: "Читать".
  - Hover: светлее (`--accent-hover`) + лёгкий подъём/тень
    (`box-shadow: 0 4px 20px rgba(124,58,237,.35)`) — это допущение по
    аналогии с типичным поведением таких UI, на статичном скриншоте
    состояние hover не видно.
  - Active/pressed: `--accent-active`, тень убирается.
- **Secondary/outline** — прозрачный фон, тонкая обводка `--border-subtle`
  или белая полупрозрачная, круглая форма. Пример: круглая кнопка "+"
  рядом с "Читать" на hero.
- **Ghost** — без фона и обводки, только текст/иконка + текст. Пример:
  "Открыть всю историю" (с иконкой часов), "Все →" (ссылки секций).

### Карточки тайтла (сетка каталога)

- Обложка — вертикальная (соотношение ~2:3), `radius-md`, `object-fit: cover`.
- Поверх обложки, левый верхний угол — бейдж рейтинга: тёмный
  полупрозрачный фон (`rgba(0,0,0,.55)`) + жёлтая звезда + число, `radius-sm`.
  Если новинка — вместо/вместе с рейтингом бейдж "NEW" на фиолетовой заливке.
- Под обложкой: название (`body`, bold, 1 строка с обрезкой `…`), затем
  "Глава NNN" (`caption`, `--text-secondary`).
- Hover карточки (допущение): лёгкое увеличение (`scale(1.03)`) + тень —
  стандартный паттерн для таких каталогов, зафиксировать при первой
  вёрстке и проверить с пользователем.

### Карточка "Продолжить чтение" (список)

Горизонтальная: маленькая обложка слева (квадрат/thumbnail, `radius-sm`),
название + "Глава NNN" по центру, иконка "···" (меню) справа от текста,
под всем этим — тонкий прогресс-бар (`--accent` заливка на треке
`--border-subtle`) и процент числом справа от бара.

### Список "Последние обновления"

Иконка обложки (маленькая, квадрат/скруглённая), название, бейдж "NEW"
(фиолетовая плашка, белый текст, если обновление свежее), справа —
относительное время ("5 мин назад", `--text-tertiary`).

### Чипы категорий

Pill-форма, иконка + текст, тонкая обводка `--border-subtle`, фон чуть
светлее базового. Последний элемент ряда — "Все категории →" уже как
solid-кнопка с `--accent`.

### Промо-карточка Premium (сайдбар) / Sync (правая панель)

Прямоугольник `radius-lg`, фон — тёмный с фиолетовым свечением/градиентом
по краю или фоновой иллюстрацией (силуэт персонажа на фоне ночного неба,
фиолетовое свечение — сгенерировать в этом стиле, см. п.7). Заголовок bold,
короткое описание `body-sm` `--text-secondary`, primary-кнопка снизу.

### Навигация (сайдбар, веб)

Вертикальный список, каждый пункт: иконка (20px) + текст, паддинг
~10px×12px, `radius-md`.
- **Активный пункт** — заливка `--bg-surface-hover`, иконка и текст
  становятся ярче/белее (возможно иконка приобретает `--accent` — на
  референсе именно фон-подсветка, а не цветная иконка).
- **Обычный пункт** — иконка/текст `--text-secondary`.
- **Hover** (допущение) — тот же фон, что активный, но чуть слабее
  (`--bg-surface`), для обратной связи при наведении.

### Нижний таб-бар (мобильная версия)

4 пункта (Главная, Поиск, Библиотека, Профиль), иконка сверху + подпись
снизу (`caption`), активный — иконка+текст в `--accent`, неактивный —
`--text-secondary`. Фон бара — `--bg-sidebar`, тонкая верхняя граница
`--border-subtle`.

### Сегментированный переключатель (настройки чтения)

Например "Вертикальный / Горизонтальный", "Слева направо / Справа налево":
контейнер `--bg-input`, `radius-full`, два таба, активный таб — заливка
`--accent`, белый текст, скругление pill внутри контейнера. Неактивный —
прозрачный, `--text-secondary`.

### Слайдеры (яркость, размер текста)

Трек `--border-subtle`, заполненная часть до бегунка — `--accent`, бегунок
— белый кружок с лёгкой тенью.

### Поле поиска

Pill-форма (`radius-full`), фон `--bg-input`, иконка лупы слева
(`--text-secondary`), плейсхолдер `--text-secondary`, справа — бейдж
подсказки горячей клавиши "Ctrl /" (маленький, `radius-sm`, обводка).

### Инпут-состояния (общее допущение для форм, на скрине форм нет)

- Default: `--bg-input`, обводка `--border-subtle`
- Focus: обводка `--accent`, лёгкое фиолетовое свечение
- Error: обводка `--danger`
Эти состояния не показаны на референсах — вводим по стандартной практике,
скорректируем при первой реальной форме (например, авторизация в v2).

## 6. Иконки

Стиль — тонкая линия (line icons), похоже на набор в духе **Lucide**
(бесплатный, хорошо сочетается с Inter, есть React-пакет `lucide-react`).
Берём его как рабочий набор.

## 7. Обложки и баннеры

С 2026-07-26 обложки — настоящие, с MangaDex API (см. ARCHITECTURE.md,
"Источник контента"). Резервный градиент в фирменной палитре
(фиолетовый/красный/синий, детерминированный по id тайтла — см.
`gradientForId` в `src/services/content/mappers.ts`) остаётся как
fallback: показывается, если у тайтла нет обложки на MangaDex или
картинка не загрузилась (см. `CoverPlaceholder`, компонент сам
переключается на градиент через `onError`). Специально генерировать
обложки/баннеры больше не нужно.

## 8. Как добавить новый язык интерфейса (без программирования)

Все тексты интерфейса (кнопки, заголовки разделов, пункты меню) лежат
в отдельных файлах-словарях — по одному файлу на язык:
`src/i18n/locales/ru.json`, `en.json`, `es.json` и так далее. Каждый
файл — это просто список "ключ: перевод", например:

```json
{
  "nav": {
    "home": "Главная",
    "search": "Поиск"
  },
  "common": {
    "read": "Читать"
  }
}
```

**Чтобы поправить перевод на уже существующем языке**: открыть нужный
файл (например `es.json` для испанского), найти строку с нужным ключом
(слева от двоеточия — тот же для всех языков, справа — текст на этом
языке) и заменить только текст справа, не трогая сам ключ и кавычки.

**Чтобы добавить совсем новый язык**, которого нет в списке:
1. Скопировать `en.json` в новый файл, например `it.json` (для
   итальянского) — так гарантированно ничего не потеряется, а переводить
   можно постепенно поверх английского текста.
2. Перевести значения (то, что справа от двоеточия) на новый язык, не
   трогая ключи слева.
3. Показать разработчику (или следующей сессии Claude) — он подключит
   файл в `src/i18n/index.ts` и добавит язык в список выбора
   (`src/i18n/languages.ts`) двумя короткими строчками. Вёрстку и логику
   при этом трогать не нужно — она одна и та же для всех языков.

Сейчас `ru` и `en` переведены полностью. Ещё 8 языков (`kk`, `es`, `fr`,
`de`, `tr`, `ko`, `zh`, `ja`) — рабочие заготовки: короткие слова в меню
переведены, часть более длинных описаний — ещё нет (см. DECISIONS.md,
запись про заготовки языков). Их можно смело редактировать по инструкции
выше, ничего не сломается — просто пока не весь текст на них
переведён.

## 9. Светлая тема (с 2026-07-27)

Переключатель "Тема: Тёмная/Светлая" на референсах намекал, что светлая
тема задумана — реализована по запросу пользователя. Механизм: атрибут
`data-theme="light"` на `<html>`, переопределяющий фоновые/текстовые
токены в `src/styles/tokens.css` (см. `:root[data-theme='light']`) —
акцентный красный и служебные цвета (`--danger`, `--rating-star`,
`--success`) одни и те же на обеих темах, разница только в
фонах/поверхностях/тексте.

| Токен | Тёмная | Светлая |
|---|---|---|
| `--bg-base` | `#0A0A0F` | `#FAF9FB` |
| `--bg-sidebar` / `--bg-surface` | `#0D0C13` / `#15141C` | `#FFFFFF` |
| `--bg-surface-hover` / `--bg-input` | `#1C1B26` / `#17161F` | `#F2F0F4` |
| `--border-subtle` | `#232230` | `#E4E1E8` |
| `--text-primary` | `#F5F5F7` | `#16151A` |
| `--accent` | `#4CAF7D` | `#368A5C` (чуть темнее для контраста на белом) |

**Читалка (Reader) остаётся всегда тёмной**, независимо от темы сайта —
осознанное решение, не баг: у большинства читалок манги/PDF/видео тёмный
фон принят по умолчанию для комфорта чтения (страницы манги и так
светлые/белые, тёмная рамка вокруг их не спорит с их собственными
цветами). См. DECISIONS.md.

## 10. Что не видно на скриншотах и придётся додумать

- Состояния ошибок, пустых списков (empty state), загрузки (skeleton/spinner).
- Брейкпоинты и поведение сайдбара/правой панели на планшете и мобильном
  вебе (мобильный референс — это отдельное нативное/PWA-подобное
  приложение с таб-баром, не адаптив веб-версии).
