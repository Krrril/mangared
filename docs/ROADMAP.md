## Следующие 4 шага — строгий порядок

Зафиксировано 2026-07-27: не начинать следующий пункт, пока не закрыт
предыдущий. Порядок не случайный — каждый следующий шаг зависит от
результата предыдущего:

1. **[x] Перенос гостевых данных (localStorage → аккаунт)** — при
   успешном входе/регистрации. Реализовано и проверено вживую, см.
   DECISIONS.md.
2. **[ ] Деплой на реальный хостинг** — фронтенд на Vercel/Netlify,
   бэкенд + PostgreSQL на Railway/Render, публичный домен вместо
   `localhost`. *Почему после переноса данных*: бессмысленно давать людям
   регистрироваться на проде, если их гостевой прогресс на локальной
   версии потом никуда не денется — сначала должна быть рабочая логика
   миграции, потом уже реальные пользователи.
3. **[ ] Подключение реального `GOOGLE_CLIENT_ID`** — ручной шаг
   владельца проекта (Google Cloud Console → Authorized JavaScript
   origins → домен из шага 2). *Почему после деплоя*: Google требует
   указывать конкретный домен при создании client ID — без реального
   домена с шага 2 его физически не с чем связать (localhost можно
   добавить для разработки, но постоянный рабочий client ID привязывается
   к продовому домену).
4. **[ ] Мобильная обёртка (Capacitor) — Android (.apk) и iOS (.ipa)**
   поверх уже задеплоенной и стабильной веб-версии. *Почему последней и
   почему именно так*: Capacitor не переписывает приложение — он
   упаковывает уже готовый сайт в нативную оболочку. Если делать обёртку
   до того, как веб-версия задеплоена и стабильна (шаги 2–3), любое
   изменение бэкенда/фронтенда пришлось бы тестировать и накатывать
   дважды — в вебе и в уже собранных мобильных билдах. Сначала сайт
   должен "устояться" на реальном хостинге, потом одна обёртка вокруг
   готового результата.

Дальше в v2/v3 — уже не такой жёсткий порядок, можно комбинировать.

## Не по фазам, а по мере надобности

Полноценный брендинг (лого, философия, tone of voice) — самостоятельная
задача, которую можно делать параллельно с любой фазой, как только
появится время/желание. Название уже зафиксировано — **MangaGreen**
(см. DECISIONS.md), остальное (лого, тон общения) — бэклог.
