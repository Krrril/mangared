# PROJECT.md — MangaRed

## Что это

**MangaRed** — веб-приложение (позже и мобильное) для чтения манги, манхвы и маньхуа.
Тёмная тема, фиолетовый акцент, минимализм в духе современных стриминговых
сервисов (Netflix / Crunchyroll-style каталог + читалка).

Технически — SPA на React, с прицелом на переиспользование логики в React
Native, когда дойдём до мобильных приложений.

## Аудитория

Читатели манги/манхвы/маньхуа, привыкшие к мобильным читалкам (типа Mangadex,
Tachiyomi, Asura Scans и т.п.), которые хотят:
- Быстро найти и продолжить читать с того места, где остановились
- Комфортный ридер (вертикальный/постраничный, регулировка яркости/размера)
- Синхронизацию прогресса между устройствами
- Каталог с рейтингами, жанрами, обновлениями глав

## Откуда взялся проект

Изначально задумывался под названием "MangaVerse" как очень масштабный
концепт — есть черновой документ-оглавление (`MangaVerse_Master_Plan.docx`)
на 30 потенциальных глав спецификации (Vision, PRD, SRS, Design System,
Backend, Admin Panel, AI, Recommendation System, Offline, Security и т.д.),
плюс идеи по монетизации, полноценной админке, брендингу и трёхлетнему
роадмапу.

**Решение**: не пытаться сразу написать спецификацию на 30 глав. Вместо
этого — 5 живых файлов в `/docs` (этот файл и соседние), которые растут
вместе с проектом, плюс поэтапный `ROADMAP.md`, куда амбиции из
мастер-плана распределены по фазам MVP → v2 → v3. Причина см.
[DECISIONS.md](DECISIONS.md).

**Название**: финально — **MangaRed** (не MangaVerse). Используется
везде в коде, UI и документации.

## MVP-фичи (первая версия)

Цель MVP — рабочий сквозной путь пользователя на моках данных, без бэкенда:

1. **Главная страница** — hero-баннер с featured-тайтлом, горизонтальные
   подборки ("Популярное сегодня", "Продолжить чтение", "Новинки"),
   категории, сайдбар с навигацией.
2. **Страница тайтла** — обложка, описание, рейтинг, список глав, кнопка
   "Читать".
3. **Читалка (Reader)** — постраничный/вертикальный просмотр страниц
   главы, базовые настройки (яркость, размер, направление чтения).
4. **Поиск и каталог** — список тайтлов с фильтрами по жанру.
5. **"Продолжить чтение"** — локальное сохранение прогресса (localStorage
   на этом этапе, без бэкенда).

Всё остальное (авторизация, бэкенд, синхронизация, админка, AI-фичи,
монетизация) — сознательно вынесено в [ROADMAP.md](ROADMAP.md) на более
поздние фазы, чтобы не утонуть в объёме до того, как появится работающий
продукт.

## Дизайн-референсы

Два скриншота, приложенные пользователем:
1. Мобильная версия — набор экранов (главная, поиск, библиотека, тайтл,
   читалка, настройки чтения, профиль, выбор языка)
2. Веб/десктоп версия — главная с сайдбаром

Разбор в деталях — [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).

## Юридический принцип (важно держать в голове)

Контент манги должен браться из источников, с которыми это легально —
собственный контент, лицензированные API, партнёрства или пользовательская
загрузка через модерацию. Это напрямую влияет на архитектуру (см.
"адаптер источника контента" в [ARCHITECTURE.md](ARCHITECTURE.md)) и на
допустимые способы монетизации в будущем (см. ROADMAP, фаза v3).
На старте MVP используются моковые/сгенерированные данные — вопрос
реального источника контента открыт, см. DECISIONS.md.
